# rec.verter — CLAUDE.md

Достаёт звук из видео прямо на телефоне. Без сервера, без рекламы, без лимитов.
Дальше — расшифровка речи, тоже на устройстве.

Этот файл — карта репозитория и архитектурный контракт.

## Главное правило

> **Ничего не уходит с устройства.** Ни файла, ни метрики, ни события аналитики.
> Приложение обходится без сетевых разрешений вообще, и это проверяется манифестом.

Отсюда и продукт (работает офлайн, мгновенно), и позиционирование (нечего сливать),
и снятый юридический риск: голос — биометрические персональные данные, но если он
никуда не передаётся и не хранится, режим 572-ФЗ не наступает.

## Архитектура

Три слоя, зависимости строго в одну сторону: **ui → bridge → media**.

```
src/                                     TypeScript
├── ui/                                  экраны и компоненты
├── media/                               ЕДИНСТВЕННОЕ место, знающее про NativeModules
└── formats/                             описание форматов: расширение, подпись, цена в скорости

android/app/src/main/java/com/hardelele/recverter/
├── media/                               чистый Kotlin, про React Native не знает
│   ├── AudioExtractor.kt                demux аудиодорожки → m4a, без перекодирования
│   ├── PcmDecoder.kt                    MediaCodec → PCM; переиспользуется WAV, MP3 и будущим ASR
│   ├── WavWriter.kt                     PCM → WAV
│   └── Mp3Encoder.kt                    PCM → MP3 через LAME (появится позже)
└── bridge/                              ReactContextBaseJavaModule: только преобразование типов
    ├── ShareIntake.kt                   файл, пришедший из «Поделиться»
    └── SourcePicker.kt                  системный выбор файла: запуск интента и URI
```

**`media/` не импортирует ничего из React Native.** Это не эстетика: слой должен
запускаться в обычном Android-тесте без Metro и моста, иначе проверять конвейер
можно будет только руками на устройстве.

**`bridge/` не содержит логики.** Принял аргументы, вызвал `media`, вернул результат,
перевёл исключение в код ошибки. Если в мосту появляется `if` про формат — он написан
не там.

**`src/media/` — единственный модуль в TypeScript, где встречается `NativeModules`.**
Экраны вызывают его функции и ничего не знают о мосте.

## Контракт моста

Один метод, формат — параметром. Добавление формата не добавляет метода.

```ts
convert(sourceUri: string, format: 'm4a' | 'wav' | 'mp3', options?: {
  bitrateKbps?: number      // только mp3, по умолчанию 192
  mono16k?: boolean         // приведение к 16 кГц моно, для будущего ASR
}): Promise<{
  path: string
  displayName: string       // фактическое имя в медиатеке, см. ниже
  mimeType: string
  durationMs: number
  sizeBytes: number
}>
```

Файл в приложение попадает двумя путями, и оба дают один и тот же объект:

```ts
getInitialShare(): Promise<SharedSource | null>   // файл из «Поделиться»
pickSource(): Promise<SharedSource | null>        // системный выбор изнутри приложения

type SharedSource = { uri: string; name: string; sizeBytes?: number; mimeType?: string }
```

`pickSource()` открывает `ACTION_OPEN_DOCUMENT` с типами `video/*` и `audio/*`.
Photo Picker (`ACTION_PICK_IMAGES`) не взят: он показывает только медиатеку, то есть
теряет произвольные аудиофайлы и загрузки, и не выдаёт persistable-доступ. Разрешений
`ACTION_OPEN_DOCUMENT` не требует — доступ выдаёт сам человек, выбрав файл; список
разрешений в манифесте от появления пикера не изменился.

**Отмена выбора — не ошибка**: промис завершается `null`, а не отклонением, иначе
экран показывает красную плашку там, где человек просто передумал. Отклонение здесь
одно — `PICKER_UNAVAILABLE`: открыть системный выбор нечем.

На выбранном URI берётся `takePersistableUriPermission`, поэтому файл переживает
сворачивание приложения; провайдеру разрешено persistable-доступ не выдать, и тогда
хватает метаданных, прочитанных сразу.

`displayName` возвращается потому, что запрошенное имя и записанное — разные вещи:
при совпадении MediaStore сам дописывает « (1)». Интерфейс показывает это поле,
а не собирает имя из имени исходника, иначе он врёт о том, куда сохранён файл.

Прогресс — событием `recverter:progress` с полем `0..1`. Отмена — `cancel()`.

Ошибки возвращаются кодами, не текстом: `NO_AUDIO_TRACK`, `UNSUPPORTED_CONTAINER`,
`CORRUPTED_SOURCE`, `NO_SPACE`, `CANCELLED`. Текст для человека живёт в TypeScript,
рядом с интерфейсом, и переводится там же.

`NO_AUDIO_TRACK` — только когда контейнер разобран и дорожки в нём есть, но все видео.
Не разобрался вовсе (обрезанный файл, потерянный moov) — `CORRUPTED_SOURCE`: сказать
про битый файл «в нём нет звука» значит соврать про причину.

## Форматы

| Формат | Как получается | Скорость | Что теряется |
|---|---|---|---|
| **m4a** | поток копируется из контейнера как есть | мгновенно | ничего |
| **wav** | декодирование в PCM | быстро | ничего, файл крупный |
| **mp3** | декодирование в PCM, затем LAME | медленнее | повторное сжатие |

m4a стоит первым не для красоты: это тот же звук, что в исходном видео, вынутый
без единого пересчёта. Приложения, которые «конвертируют» часовой ролик минутами,
делают ненужную работу — обычно ещё и на чужом сервере.

## Соглашения

- **Не тащить ffmpeg.** FFmpegKit ретирован (январь 2025, архив 02.07.2026) из-за
  патентной неопределённости; заброшенные форки собраны старым NDK и не проходят
  требование Google Play о 16 KB page size (обязательно с 01.11.2025). Системные
  `MediaExtractor`/`MediaCodec`/`MediaMuxer` делают ту же работу быстрее и без `.so`.
  Единственное исключение — LAME для MP3: только энкодер, LGPL, патенты истекли в 2017.
- **Любая нативная библиотека собирается свежим NDK с поддержкой 16 KB page size.**
  Иначе Play заблокирует публикацию — не «предупредит», а не даст загрузить релиз.
- **Ошибки — значения, а не исключения**, на границе моста.
- **Никакой аналитики, крашлитики и сетевых SDK.** Это противоречит главному правилу.
- Зависимости добавляются с обоснованием в описании коммита. Навигация, UI-киты и
  state-менеджеры для одного экрана не нужны.

## Инструменты

Офлайн-скрипты живут в `tools/` и в приложении не используются. Каждый — маленький
переиспользуемый модуль с вызовом в одну строку, а не одноразовый скрипт на сотни
строк. Перед тем как писать новый, свериться с `tools/README.md`; туда же строку
про новый. Логи и промежуточные выгрузки в репозитории не хранятся.

## Сборка

Node 22, Android SDK (platform 36, build-tools 36.0.0), JDK 21 — путь прописан в
`android/gradle.properties`. Подробности и команды — в [README](README.md).

`npx expo prebuild` повторно не запускать — затрёт правки.
